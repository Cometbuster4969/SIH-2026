## 1. Clauses that drive design (verbatim)

| ID | Verbatim clause | Where handled |
|---|---|---|
| **P1** | "Single-image understanding is a mandatory **baseline**, while the **principal focus** is joint reasoning over paired cross-modal and multitemporal imagery." | `architecture.md` §7.1 priority banner |
| **P2** | "At least one visual or vision-language component must be fine-tuned or otherwise adapted using BigEarthNet.txt **or the any open source training data**." | M1 (arch §7) |
| **P3** | "Visual question answering **shall be mandatory**. Each solution must additionally implement **either** captioning/scene description **or** text-guided region grounding." | M1 `vqa` + M1 `caption` + M3 `ground` (we do both) |
| **P4** | "Change description **or** change-based visual question answering from a bi-temporal image pair shall be mandatory. A spatial change map **may** also be generated **where reference masks are available**." | M4 + M5. Note "may" + conditional — the mask is *not* unconditionally required |
| **P5** | "The system must extract **complementary** information from a co-registered optical/multispectral and SAR image pair." | M1 2-image + M7 + §7.3 ablation |
| **P6** | "The system must automatically select, sequence, and execute the appropriate specialist models or tools according to the query and input configuration." | Planner + registry + executor |
| **P7** | "select one or more models or tools from a **predefined registry**" | `registry.yaml` + `GET /tools` |
| **P8** | "configure **only permitted** task parameters" | Guardrail param whitelist |
| **P9** | "provide an auditable execution summary containing the selected task, model/tool names, and key parameters." | Trace panel + PDF §4 + `trace.json` |
| **P10** | "only the observable execution trace … will be evaluated. **Internal reasoning text is neither required nor evaluated.**" | `architecture.md` §2 principle 2 — do not surface CoT |
| **P11** | "PNG and JPEG inputs may be accepted **only for the prescribed public benchmark datasets**." | Ingest allow-list gate |
| **P12** | "A generic LLM or VLM without remote-sensing adaptation **will not satisfy the requirements**." | C5 / zero-shot → adapted table |
| **P13** | Deliverables: "An interactive GUI or web application with an agentic remote-sensing AI backend, **Codes and models including test and demonstration**." | §A.6 — *test* and *demonstration* are named deliverables |
| **P14** | "The ISRO/SAC evaluation set will contain pre-georeferenced and co-registered **Cartosat-2S optical and RISAT SAR** image pairs, with task-specific reference answers, labels, bounding boxes, **or masks**, as applicable. Evaluation annotations will not be disclosed." | Resolution/sensor-agnostic tiling; §A.7 |
| **P15** | "Scores will be **normalised** before combining different metrics." | Balanced performance matters more than one spiked metric |

## 2. Representative queries (verbatim — use these exact strings in the demo)

1. "Describe the land-cover and major objects visible in this image."
2. "Highlight the water body referred to in the query."
3. "What changed between these two dates, and where did the change occur?"
4. "Use the optical and SAR images together to identify built-up and water-covered regions."
5. "Has the built-up area increased, decreased, or remained unchanged?"

**Note:** the PS gives **no verbatim single-image VQA query**, although VQA is the mandatory
baseline (P3). Queries 1 and 2 are captioning and grounding. Supply a benchmark-style VQA
question of our own for that demo (e.g. "Is there a water body in this image?").
